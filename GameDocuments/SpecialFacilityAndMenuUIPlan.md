# 특화 시설 및 선택 메뉴 개선 계획

## 목표

- 특화 시설 버튼이 눌리지 않는 이유를 사용자가 즉시 이해할 수 있게 하고, 선택 가능 시 기존 특화 시설 모달이 확실히 열리게 합니다.
- 인물 선택 메뉴의 초상화 규격과 카드 정보 계층을 통일합니다.
- 모든 화면은 고정 UGUI 프리팹으로 구성하고 런타임 동적 UI 생성은 사용하지 않습니다.

## 현재 확인 사항

- 특화 시설 8종의 ScriptableObject 데이터, 아이콘, 실제 게임 효과, 선택 스냅샷과 선택 모달은 이미 구현되어 있습니다.
- 영지 화면의 특화 시설 명령은 `PendingSpecialFacilityChoice`가 `true`일 때만 `interactable`이 됩니다.
- 특화 시설 프리팹은 MainScene의 `WIUIScreenManager.screenPrefabs`에 등록되어 있고, 옵션 버튼·아이콘·문구 참조도 직렬화되어 있습니다.
- 따라서 우선 조사 대상은 확장 완료 상태 전달, 버튼 비활성 피드백, 이벤트 구독 시점, 모달 Canvas 입력 순서입니다.

## 1단계: 특화 시설 진입 결함 재현 및 원인 확정

1. QA 메뉴 `WI/QA/Preview/Special Facility UGUI`로 선택 권한이 있는 상태를 강제해 모달 열림을 확인합니다.
2. 일반 플레이에서 성 확장 완료 전·진행 중·완료 후의 `PendingSpecialFacilityChoice`, 슬롯 수, 버튼 `interactable` 상태를 비교합니다.
3. 클릭 시 `ExecuteUGUITerritoryCommand(ChooseSpecialFacility)`에서 `UGUISpecialFacilityRequested`를 거쳐 모달 `Open()`까지 호출되는지 확인합니다.
4. 모달이 호출되지만 보이지 않으면 Canvas 정렬 순서, GraphicRaycaster, 상위 Canvas 활성 상태를 점검합니다.
5. Unity 콘솔 오류와 누락 참조를 확인하고 재현 조건을 기록합니다.

## 2단계: 특화 시설 UX 정리

- 선택 권한이 있을 때: 버튼을 강조하고 `선택 가능` 배지를 표시하며 8종 카드 모달을 엽니다.
- 확장 전 또는 권한이 없을 때: 버튼을 완전 무반응 상태로 두지 않고, 클릭 가능한 안내 상태로 유지하여 `성 확장 완료 후 선택할 수 있습니다`를 공통 메시지 모달에 표시합니다.
- 슬롯이 가득 찼을 때: 보유 시설 보기 기능으로 전환하고 각 시설 효과를 확인할 수 있게 합니다.
- 시설 카드에는 아이콘, 이름, 핵심 효과, 적용 대상, 중복 선택 불가 상태를 고정 영역으로 표시합니다.
- 최종 선택 전 확인 단계를 두고, 선택 후 영지 슬롯·월간 수입/사업 예상치가 즉시 갱신되게 합니다.

## 3단계: 인물 선택 메뉴 시안 적용 기준

- 4개 고정 카드와 페이지 이동 구조를 유지합니다.
- 모든 초상화는 동일한 마스크 영역과 비율을 사용하고 카드 밖으로 넘치지 않게 합니다.
- 카드 정보는 상태 배지, 이름, 피로·명성, 선택 버튼 순으로 고정합니다.
- 선택 카드는 냉색 청색 테두리로만 강조하고 노란 노을 색조는 사용하지 않습니다.
- 초상화가 없는 인물은 교체 가능한 빈 이미지 슬롯과 명시적인 비활성 상태를 사용합니다.
- 기존 프리팹을 수정하며 런타임에서 카드나 이미지를 동적으로 생성하지 않습니다.

## 검증 기준

- 확장 전 클릭 시 안내가 표시되고, 확장 완료 후 같은 버튼으로 특화 시설 모달이 열립니다.
- 시설 선택 후 중복 추가가 불가능하며 슬롯 수와 실제 효과가 저장/불러오기 후에도 유지됩니다.
- 1920×1080과 대표 모바일 종횡비에서 초상화, 문구, 버튼이 겹치거나 잘리지 않습니다.
- 키보드·마우스·터치 입력과 Escape 닫기를 확인합니다.
- 관련 EditMode 테스트, Unity 컴파일, 콘솔 오류 0건을 확인합니다.
