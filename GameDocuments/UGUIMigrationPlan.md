# UI Toolkit → UGUI 이식 계획

## 목표

- 현재 UI Toolkit 화면과 연결된 실제 게임 이벤트, 상태 갱신, 팝업 흐름을 UGUI로 이전합니다.
- 이식 중에는 기존 UI Toolkit을 병렬 유지하고, 화면별 동작 동등성 확인이 끝난 뒤 해당 화면만 비활성화합니다.
- UI는 에디터에서 확인 가능한 프리팹으로 제작하며 런타임 코드로 동적 생성하지 않습니다.
- `WIAdministrationUIController`에 집중된 책임을 화면별 구성 요소와 게임 서비스로 분리합니다.

## 기준 구조

| 책임 | 신규 구성 | 역할 |
| --- | --- | --- |
| 전체 화면 전환 | `WIAdministrationUGUIRootController` | 화면 표시 전환과 공용 상태 전달만 담당 |
| 캠페인 타이틀 | `WICampaignTitleUGUIController` | 난이도·시작 조건 선택과 캠페인 시작/이어하기 |
| 월드 HUD | `WIAdministrationWorldUGUIController` | 상단 자원, 좌우 패널, 하단 메뉴 갱신 |
| 지도 상호작용 | `WIAdministrationMapUGUIController` | 성 노드 선택, 지도 입력, 선택 표시 |
| 영지 화면 | `WIAdministrationTerritoryUGUIController` | 선택 성의 내정·인물·시설 표시와 명령 |
| 팝업 | 기능별 `...UGUIController` | 목표, 보고, 전투 등 서로 독립적인 팝업 처리 |
| 게임 규칙 | 기존 런타임 서비스와 ScriptableObject | UI와 분리된 캠페인·턴·저장·전투 로직 유지 |

각 화면 컨트롤러는 자기 프리팹의 직렬화된 참조와 사용자 입력만 소유합니다. 캠페인 상태를 직접 생성하거나 저장 규칙을 중복 구현하지 않고 기존 서비스 API를 호출합니다.

## 이식 순서

1. 캠페인 타이틀
   - 고정 UGUI 프리팹, Dynamic TMP 폰트, 새 캠페인/자동 저장 연결
   - 레거시 `Text`와 프리팹 내부 중복 `EventSystem` 금지 테스트
2. 월드 화면 뼈대
   - UGUI 루트, 상단 자원, 좌측 영지 요약, 우측 목표·알림 분리, 하단 메뉴
3. 지도와 성 선택
   - 성 노드, 선택 상태, 월드/영지 화면 전환
4. 영지 관리
   - 영웅 배치, 시설, 사업, 성 정보 화면을 기능별 컨트롤러로 분리
5. 팝업
   - 캠페인 목표, 월간 보고, 전투·외교·연구 팝업을 개별 프리팹으로 이식
6. 제거 단계
   - 화면별 입력·표시 동등성 테스트 통과 후 대응 UXML/USS 연결 해제
   - `WIAdministrationUIController`에서 이전 완료된 UI 필드와 이벤트 처리 제거

## 거대 컨트롤러 해체 원칙

- 한 번에 전체 클래스를 재작성하지 않습니다.
- 화면 하나를 이식할 때 해당 화면의 조회, 이벤트 바인딩, 표시 갱신을 새 컨트롤러로 함께 옮깁니다.
- 캠페인/턴/저장/전투 계산은 UI 컨트롤러로 옮기지 않고 서비스 또는 별도 책임 클래스로 유지·추출합니다.
- 새 UGUI 화면이 기존 UI Toolkit 화면과 같은 결과를 내는지 확인한 뒤 기존 partial 파일의 대응 코드를 제거합니다.
- 이행 중 필요한 임시 호출 창구는 최소한의 공개 메서드로 제한하고, 최종 단계에서 화면 전용 인터페이스로 교체합니다.
